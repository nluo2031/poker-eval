# poker-eval

A fast Texas Hold'em hand evaluator and a heads-up postflop GTO solver built on top of it, in C.

- **Evaluator:** 7-card hand ranks in ~6–9 ns, verified exhaustively against a slow reference implementation on all 133,784,560 seven-card hands.
- **Solver:** computes an approximate Nash equilibrium for a flop, turn or river spot with Discounted CFR. It outputs per-hand strategies and EVs, and solves turn spots in about 2 seconds and flop spots in minutes on a laptop.

## Build

```sh
make            # builds verify, bench, solver
make test       # evaluator tests + exhaustive verification + solver tests
```

Needs a C compiler and Python 3 (Python generates the lookup tables and runs the tests).

---

## Hand evaluator

`eval7.h` is header-only. Cards are ints `0..51` (`4*rank + suit`, deuce = 0). `eval7(cards)` returns `1..7462`, higher is better (7462 = royal flush).

How it works: with 7 cards at most one suit can have 5 or more, and a flush always beats anything else 7 cards can make. So a hand is either

- a flush: look up the 13-bit rank mask of the flush suit in `FLUSH_TABLE`, or
- not a flush: compute a perfect-hash index of the rank-count vector and look it up in `NONFLUSH_TABLE`.

Suit counts are tracked in packed 4-bit lanes biased by 3, so "is there a flush" is a single mask test.

The tables are generated by `tables.py` from `eval5.py`, a deliberately slow, obviously correct 5-card evaluator.

**Verification** (`./verify`):
1. The C port of the reference evaluator matches Python on all 2,598,960 five-card hands.
2. `eval7` matches the best-of-21-subsets oracle on all 133,784,560 seven-card hands.
3. Category frequencies match the known 7-card distribution, and exactly 4,824 distinct ranks are reachable.

**Speed** (`./bench`, Apple M5, one thread):

| Workload | Hands/s | ns/hand |
|---|---|---|
| Random hands from an array | 107 M | 9.4 |
| Full enumeration in nested-loop order | 158 M | 6.3 |

### Options

| Option | Meaning |
|---|---|
| `--board` | 3–5 cards, e.g. `Ks7h2d` |
| `--oop`, `--ip` | Ranges: `QQ+`, `99-66`, `AKs`, `AQo:0.5`, `KTs+`, `A5s-A2s`, `AhKh`, `random` |
| `--pot`, `--stack` | Starting pot and effective stack behind |
| `--bet`, `--raise` | Sizes in % of pot (raises: % of the pot after calling). Default `33,75` and `75` |
| `--flop-bet` … `--river-raise` | Per-street overrides |
| `--raise-cap N` | Max raises per street (default 3) |
| `--no-allin` | Don't add an all-in option at every decision |
| `--iters`, `--target`, `--check` | Stop after N iterations or at a target exploitability (% of pot, default 0.3), checked every N iterations |
| `--show PATH` | Print a node, e.g. `"X B75 C Td"` (actions and dealt cards). Repeatable |
| `--combos N\|all` | Rows per printed node |
| `--threads N`, `--max-mem GB`, `--no-iso` | Threads, tree-size limit, disable suit isomorphism |

OOP acts first on every street. Bets at least as large as the remaining stack become all-in.

### How it works

**Game model.** The solver solves the abstracted game you specify: fixed ranges, board, pot, stacks and bet menu. It finds an equilibrium of that game, not of real no-limit hold'em with continuous bet sizes.

**Public tree with hand vectors.** Actions are public; only hole cards are hidden. So the tree is built once over public actions and dealt cards, and every node carries vectors indexed by each player's hands: reach probabilities going down, counterfactual values coming up. One traversal updates the information sets "this node × each of my hands" for every hand at once.

**Discounted CFR** (Brown & Sandholm, 2019) with α = 1.5, β = 0, γ = 2 and alternating updates. Each information set runs regret matching on its counterfactual regrets; the reach-weighted average strategy converges to a Nash equilibrium.

**Terminal values with card removal.** An opponent hand that shares a card with mine is impossible, so each terminal value is a sum over compatible opponent hands only:

- **Fold:** inclusion–exclusion. Total opponent reach, minus the reach of opponent hands holding either of my cards, plus the identical combo, which was subtracted twice. O(n).
- **Showdown:** both hand lists are presorted by strength once per river board. A single ascending sweep with per-card running sums gives, for each of my hands, the compatible opponent reach I beat, tie and lose to. O(n) per node instead of O(n²).

**Chance nodes** zero the reach of hands that hold the dealt card, and average children over the cards compatible with both players' hands.

**Suit isomorphism.** If a suit permutation maps the board and both ranges onto themselves, it maps the subtree after card *c* onto the subtree after its image. Only one card per equivalence class gets a subtree; the others reuse its values through a hand-index permutation. On a monotone flop, the turn's 49 cards collapse to 23.

**Exploitability.** A best-response pass for each player against the average strategy gives (BR₀ + BR₁ − pot) / 2. This is how far from equilibrium the strategy is, and it's the stopping criterion.

**Parallelism.** Children of chance nodes are independent within an iteration, so they're solved in parallel across threads. Scaling is about 6.2× on a 10-core M5.

### Performance

Apple M5, 10 threads. The ranges are the ones from the example above.

| Spot | Tree | Memory | Time |
|---|---|---|---|
| Turn, bets 50/100%, raise 75% | 11 K nodes | 0.02 GB | 0.2% of pot in 1.6 s |
| Flop, bets 33/75%, raise 75%, 2 raises/street, rainbow (Ks7h2d) | 2.26 M nodes | 3.84 GB | ~0.75 s/iteration |
| Same, two-tone (Ks7s2d) | 1.38 M nodes | 2.34 GB | 1.7× faster than without isomorphism |
| Same, monotone (Ks7s2s) | 0.65 M nodes | 1.11 GB | 3.2× faster than without isomorphism |

A full rainbow flop solve with this menu reaches about 0.4% of pot in roughly 200 iterations.

### Validation

`test_solver.py` checks the solver against cases with known answers:

1. **Polarized river.** OOP has sets plus air, IP has only bluff-catchers, and the only bet is pot-size. Theory says bluffs make up 1/3 of OOP's betting range and IP calls 50% (minimum defense frequency). After card removal that means each air combo bets exactly 4.17%. The solver gets 4.17% and 50.0%, and exploitability reaches about 0.
2. **Convergence on a realistic turn spot.** Exploitability falls below 0.5% of pot, and the two players' root EVs sum to the pot.
3. **Isomorphism.** The merged tree is smaller, matches the unmerged tree's exploitability and EVs, and a river card followed through a merged subtree shows exactly the suit-swapped strategy.

### Limitations

- Postflop only, heads-up only, fixed bet-size menu (the same for both players).
- Regrets and strategies are stored as 32-bit floats, so flop trees with many bet sizes can exceed 16 GB of RAM.
- Text output only.

### Possible next steps

- 16-bit compressed regrets and strategy sums, to halve memory.
- Cache the current strategy between the two players' passes (about 20% of runtime).
- Monte Carlo CFR (sampling turn and river cards) for larger trees.
